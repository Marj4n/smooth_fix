SMOOTH FIX 1.0.5 — ADVANCED4
Build internal: 1.0.5-perf-r2-advanced4
Minecraft 1.20.1 Fabric. Versi publik tetap 1.0.5.

PASANG DAN JALANKAN
1. Ganti Smooth Fix lama dengan JAR Advanced4 pada client DAN server.
2. Buat salinan save modpack asli dan buka salinan itu. Command tidak membuat backup.
3. Jalankan sebagai operator; advanced membutuhkan satu player saja.
   Jika config advanced lama masih berisi suite pendek, rename file
   config/smooth_fix/advanced_benchmark.json menjadi advanced_benchmark_lama.json
   sebelum start agar default 21 stage dibuat. Simpan config custom jika dibutuhkan.
4. Gunakan /smoothfix stress advanced start world-copy
5. Status: /smoothfix stress advanced status
6. Stop dan recovery: /smoothfix stress stop
7. Tetap fokus ke game. Inventory, chest dan layar EMI boleh terbuka oleh controller.

TNT, Wither, mining, generated chunks, loot personal Lootr, advancement dan efek global
mod dapat mengubah salinan save secara permanen. Inventory asli dan state player yang
dijurnal dipulihkan; terrain/loot/advancement bukan bagian rollback player.
Jangan menjalankan command ini pada save utama yang ingin dipertahankan.

SUITE DI WORLD ASLI
21 stage default, masing-masing 60 detik aksi, ditambah sampai 3 struktur mod terpilih:
panorama, rute terrain loaded, rute chunk baru, kunjungan ulang rute yang sama,
struktur village, chest, Lootr, inventory/tooltip/hotbar, EMI search, EMI recipe,
combat 32, effects 64, Blood Moon native, Wither 10, TNT 16, block breaking,
cuaca, teleport, Nether, End, dan save.

Config dibuat di config/smooth_fix/advanced_benchmark.json. Durasi 10–300 detik,
jumlah mob maksimum 64, Wither maksimum 10, TNT maksimum 32. Modul/hook yang
belum tersedia, struktur yang tidak digenerate di dimension, atau terrain TNT yang
tidak sesuai dicatat sebagai skipped. Struktur mod dicari dari registry.
Suite default dapat membutuhkan lebih dari 21 menit ditambah loading dan pencarian.
Struktur mod terpilih otomatis sekarang dijalankan SETELAH stage utama (sebelum save),
sehingga pencarian struktur langka tidak menghalangi chest/EMI/combat/dimensions.
optionalModStructureSearchSeconds default 90 (10–600). Jika habis, struktur opsional
skipped_optional_structure_search_budget dan suite lanjut. Budget ini tidak membatasi
village wajib 10.000 → 20.000 → … atau target struktur yang ditulis manual.
Field baru otomatis memakai default saat config lama dibaca; tidak perlu hapus config.

GERAKAN DAN PESAN STAGE
Controller berjalan di ground memakai collision shape pada chunk yang sudah tersedia.
A* dibagi antar-tick (maksimum 12 node / budget 0,75 ms per tick, total 256 node,
horizon lokal 12 blok). Budget waktu bersifat lunak: satu pemeriksaan collision tetap
harus selesai. Path dan waypoint dipertahankan, tidak mengejar target yang berlari
terus menurut waktu. Jika macet, edge yang gagal dihindari sementara dan jalur dihitung ulang.
Tangga satu blok memicu jump native singkat dengan cooldown; slab bisa auto-step.
Controller tidak menekan sneak. Auto-jump vanilla disupresi hanya selama benchmark agar tidak menambahkan lompatan lain; setting user tidak diubah. Dinding tinggi, plafon rendah, jurang dan lava harus
diputar; chunk yang belum tersedia tidak dipaksa load oleh pathfinding. Tidak ada
teleport sebagai jalan keluar ketika berjalan. Jika jalur tetap tidak tersedia,
HUD menampilkan status itu dan route tidak otomatis PASS.
Input benchmark di-override pada pembacaan KeyBinding, sehingga toggle sneak/sprint
milik user tidak bolak-balik ditekan oleh controller. Input netral selama loading/UI,
transisi dan perencanaan; status tombol user tidak ditimpa dan kembali setelah run.
Route wajib memiliki >=12 blok lintasan horizontal, >=8 blok perpindahan maksimum
(>=6 untuk patrol) dan >=5 sampel gerakan. Pergeseran kecil/oscillation di dinding
bukan bukti route berhasil. Detail navigation disimpan di satu laporan client.

HUD kiri atas: stage/total, tujuan aksi, pencarian radius/kandidat atau waktu tersisa,
status navigasi, serta stage berikutnya. Pesan chat mengumumkan awal, hasil stage,
dan akhir run/recovery. HUD menambah sedikit biaya render; bandingkan build yang sama.
Navigasi ini tidak mencakup swimming, climbing ladder, membuka pintu, atau traversal
semua mechanic mod. Terrain yang tidak dapat dilalui dilaporkan, bukan dianggap sukses.

PENCARIAN VILLAGE / STRUKTUR
Default mencari dari posisi player saat stage dimulai: radius 10.000 blok, lalu
20.000, 30.000 dan seterusnya. Setiap perluasan hanya memeriksa band baru.
Pencarian village wajib dan target custom berlanjut sampai struktur ditemukan, batas world habis, atau operator stop. Struktur mod yang dipilih otomatis punya budget pencarian tersendiri.
Radius dihitung dari posisi awal pencarian yang sama; tidak pindah pusat tiap perluasan.

Kandidat memakai placement dan seed native. Satu chunk kandidat diproses sampai
STRUCTURE_STARTS lewat future native; controller tidak menunggu/join future di tick.
Hanya tujuan yang ditemukan dimuat penuh sebelum player dipindahkan. Native worldgen
masih dapat menambah beban; ini tidak menjamin seluruh mod bebas spike.

Village default mencakup struktur bertag village, ID village mod (misalnya small/village_swamp atau oasis_village), dan anggota structure set village yang aktif. Ini mendukung penggantian anggota village vanilla oleh datapack/mod. Target hasil resolusi dicatat di resolvedStructureTargets. Target custom selain #minecraft:village tetap mengikuti ID/tag yang dipilih.
Status command menunjukkan radius aktif. Laporan stage menyimpan structureSearch:
radiusBlocks, completedRadiusBlocks, candidateChunksChecked, regionsChecked dan
elapsedMs. Progress dikirim ke client setiap dua detik agar pencarian aktif tidak
terbaca sebagai timeout loading. Stopwatch aksi 60 detik baru mulai sesudah ditemukan
serta client siap. Timeout heartbeat dan /smoothfix stress stop tetap berlaku.

Config structureSearchRadiusStepBlocks default 10000. Config lama yang belum punya
field ini otomatis memakai default baru; structureRadiusChunks lama tidak mengatur
pencarian baru. Kamu tidak perlu menghapus config Advanced2 yang sudah berisi 21 stage.

Target tidak terdaftar, generation struktur dimatikan, placement tidak tersedia,
atau batas world habis ditandai skipped lalu suite lanjut. Stage skipped tidak
memanggil validasi struktur kosong. Stop juga melepaskan ticket chunk pencarian.

Aksi pertama yang berhasil tidak mengakhiri jendela stress. Inventory dan EMI diuji
berulang; mob combat yang mati ditambah secara bertahap selama stage. Combat memakai
counter damage yang diterima, bukan jumlah paket attack. Chest memerlukan container
terbuka dan item masuk ke inventory benchmark. UI harus benar-benar dirender agar
latensi first-render tercatat. EMI recipe harus menampilkan resep yang diminta beserta
slot hasil yang cocok; worker search lama ditolak. Status run selesai tidak ditimpa
oleh disconnect berikutnya atau run baru. Blood Moon membutuhkan langit cerah;
cuaca dibersihkan saat stage dan state cuaca/forecast asli dipulihkan di akhir.
TNT memakai terrain kering yang sudah loaded, observer
dekat permukaan, dan counter blok non-air yang benar-benar menjadi air setelah ledakan
aktor benchmark. Jika tidak ada terrain kering dalam radius, stage TNT skipped.

LAPORAN — SATU FILE PER RUN PER SISI
Client: config/smooth_fix/reports/benchmark_client_<runId>.json
Server advanced: <save>/smooth_fix/advanced_benchmarks/<runId>.json
Server legacy: lihat path yang dicetak command/log.

Seluruh stage berada dalam stages[], menggunakan phase dan runId yang sama.
File client yang sama diperbarui pada checkpoint setiap stage serta akhir run.
Tidak ada file client baru per fitur. Semua frame timings, timeline, action latencies,
stack samples, error dan observasi controller disimpan dalam stage masing-masing.
Profil manual /smoothfix profileclient tetap boleh membuat laporan terpisah.

status=completed hanya jika seluruh stage terverifikasi.
completed_with_failures berarti ada workload yang gagal diverifikasi.
completed_with_skips berarti ada fitur tidak tersedia/tidak dapat diuji.
completed_pending_client_reports berarti ada laporan client belum diterima.
Stopped, loading timeout, heartbeat timeout dan disconnect mempertahankan hasil parsial.
summary memuat passed/failed/skipped/pending. Jendela pengukuran dan keberhasilan aksi
merupakan dua hal terpisah. Stage skipped tidak berarti mod berhasil dites.

RECOVERY
Journal ditulis sebelum player diubah dan tidak ditimpa jika recovery lama belum selesai.
Inventory vanilla lengkap (termasuk armor/offhand), selected slot, dimension, XYZ,
yaw/pitch, game mode, flying/allowFlying/invulnerable, fly/walk speed, health, hunger
serta XP dipulihkan. Inventory handler ditutup; inventory, hotbar dan abilities disinkron.
Journal lama dari Advanced1 tetap dapat dibaca.
recoveryVerification.all hanya hasil perbandingan SERVER terhadap journal.
clientRecoveryVerification menunjukkan hasil pengamatan CLIENT setelah paket restore.
recoveryVerifiedBothSides baru true setelah acknowledgement client yang cocok diterima.
Disconnect dapat membuat acknowledgement client tidak tersedia; journal dapat dicoba
lagi saat login. Ini tidak menjamin rollback storage/capability/advancement milik semua mod.

CARA MEMBACA PERFORMANCE
Target 120 FPS berarti budget interval frame sekitar 8.33 ms. Lihat p95/p99, maksimum,
jumlah frame >100 ms, dan frameTimeline; rata-rata FPS saja tidak cukup.
frameWorkBeforePresent tidak mengukur GPU. frameIntervals mencakup frame pacing/wait.
Server tick work memiliki budget 50 ms. tickStartIntervals mencakup scheduled sleep,
task queue dan stall di luar callback; interval sedikit di atas 50 ms bukan otomatis overload.

Recorder dimulai sebelum persiapan/teleport native supaya loading awal tidak hilang.
preparationMs/structureLocateMs terpisah dari actionWindowSeconds.
chunkAndMechanicMetrics membedakan feature generation, NBT encode/decode, dan jumlah
load/unload event. Feature generation bukan seluruh proses generate chunk. Decode/encode
bukan disk I/O; event callback bukan durasi lengkap load/unload. Rute cold hanya tervalidasi
jika hook generation benar-benar teramati. Rerun save yang sama dapat menjadi warm.
Snapshot struktur hanya membaca chunk yang sudah tersedia; tidak scan-load area tiap tick.

Untuk perbandingan sebelum/sesudah, gunakan save copy awal yang sama, posisi/seed sama,
config stage sama, modpack sama, serta setting render/simulation distance/FPS cap yang sama.
Jangan mengganti RAM atau mengurangi konten untuk menutupi hasil. Optimasi dilakukan setelah
suite memberi workload dan bukti bottleneck yang dapat dibandingkan.
